## 7. Sign-in with an e-mail code and passkeys (22.10.2026)

**What the app and the website do**
- First screen (app `/sign-in` and `/register`, website `/[locale]/account`): e-mail → 6-digit code by e-mail → signed in. A new address gets a short welcome form (first/last name, country, year of birth, terms; city, goal and news optional, nothing preselected) and the account is created with `email_verified = true`, because the code proved the address. "Sign in with password" keeps the classic form for existing accounts and the review account.
- Codes (`src/lib/emailCode.ts`, `src/app/api/auth/code/[step]`): stored only as HMAC with salt, valid 10 minutes, single use, 5 wrong attempts, per address at most 5 codes an hour and one every 30 seconds, per IP limits, reCAPTCHA on the website. The answer never says whether an address has an account. Branded HTML mail (emerald/gold) in English, German or Arabic (other languages English), plain text alongside, code in the subject so iOS can offer it from Mail (`textContentType="oneTimeCode"`).
- Passkeys (`src/lib/passkeys.ts`, `@simplewebauthn/server` and `/browser` 14, RP ID `quranmasterclass.com`, user verification required, only the public key stored): website Profile → Security (`/[locale]/account/security`) adds, renames and removes passkeys and signs in with them. In the **app** the passkey ceremony runs on the website page `/[locale]/account/passkey` inside the system sign-in sheet (`expo-web-browser` `openAuthSessionAsync` = ASWebAuthenticationSession on iOS, Custom Tab on Android). No native passkey module was added (none is maintained for Expo SDK 58 / RN 0.88 that we could verify, and a native module would need a new native build): the sheet uses the passkeys saved for quranmasterclass.com in iCloud Keychain or another provider. The app holds a secret, the page only an id; the app redeems the finished sign-in for its own session (5 minutes, once). Adding a passkey from the app uses a one-time link (10 minutes, fragment only) after a sign-in or code confirmation of the last 15 minutes.
- Security screen (app Account → Settings → Security and sign-in, website `/account/security`): ways to sign in, passkeys, signed-in devices with "sign out" per device and "sign out all other devices".
- Sensitive steps (add a passkey, delete an account without a password, set a password) need a sign-in or e-mail code confirmation of the last 15 minutes in the same session.

## 8. AI tutor Dalil / Hidaya (22.10.2026)

**What it is.** The former "assistant" is now an AI tutor for recitation and understanding of the Quran: **Dalil** (دليل, "guide" and "evidence"; drawn as a dignified sheikh) for everyone, and **Hidaya** (هداية, "guidance"; a veiled ustadha) whom sisters can choose (their default; identity from `lib/identity.ts`). Both are AI, not real scholars – the consent screen, the chat header ("AI" seal) and the note under the composer say so. Model: OpenAI `gpt-5.4-mini` (`OPENAI_TUTOR_MODEL` overrides), `reasoning_effort: none`, temperature 0.2, JSON schema output. Moderation: `omni-moderation-latest` on every question and answer.

**Grounding (no invented content).** `src/lib/tutor/*`: retrieval (BM25) over the reviewed content only – academy courses (with quiz explanations), tajweed lessons, guides, Islam chapters (incl. the 99 names), the Shams handbook and glossary, carousels; for a verse the Quran.com translation and Ibn Kathir (abridged). The model sees numbered passages and must cite them. The server rejects an answer (and answers "Allahu aʿlam – not found in our lessons" with related pages) when it cites no passage, names a verse or hadith that is not in the retrieved passages, writes vowelled Quran text, invents a quote, or writes a number that appears in no passage (one retry with the reason). Quran and hadith texts under an answer come from Quran.com / hadith-api / Thaqalayn by reference (`feed/resolve.ts`), never from the model. Fiqh questions get "views" with the documented positions and the fixed note "not a ruling – ask a qualified scholar"; off-topic, political and harmful questions get fixed polite refusals; crisis questions a fixed help message with emergency numbers. The learner's own figures (streak, verses, weakest mastery dimension, today's wird; Together counts for signed-in members, never names) are one more source – only those figures may be used.

**Privacy.** No name/e-mail is sent; e-mail addresses, phone numbers, links, the account's own name and "my name is …" are removed before sending (`privacy.ts`; names of prophets/Companions stay). Conversation only on the device (`qmc.tutor.chat.v1`, not synced) or in the browser. Server keeps only `tutor_log` (no text, no user, no IP; 180 days), `ai_usage` counters (kind `tutor`, per day), and reported answers in `tutor_reports` (scrubbed question + answer, no user/IP, 90 days). Privacy policy paragraph "AI tutor and AI features (OpenAI)" in all 14 languages.

**Limits and money.** Website: visitors `limits.assistantAnonPerDay` per IP, accounts `limits.assistantPerUserPerDay`. App: free `TUTOR_APP_FREE_PER_DAY` (default 3) per account or IP, Pro (signed in) `premium.assistantPerDay`. Burst limit 6/min per IP, platform ceiling `TUTOR_GLOBAL_PER_DAY` (default 4000 model questions). Identical first questions are answered from a cache (3 days, 800 entries). When the free questions are used up the app shows the Pro button with the App Store price only (`useProPrice`/`withPrice`). Offline, provider quota or switched off: a calm message, the conversation stays readable.

**App Privacy label (owner).** Add **User Content → Other User Content** (questions to the tutor, sent to OpenAI as processor): purpose App Functionality, **not linked** to the user, not used for tracking. Existing "Product Interaction" covers the learning figures. No change to tracking (still none).

**Age rating.** Unchanged 13+. The tutor asks for 13+ or a parent's agreement; accounts with a birth year under 13 need the parent option (server checks).
