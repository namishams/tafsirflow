# Feed (server-driven)

Endpoints: `/api/feed/config`, `/api/feed/new`, `/api/feed/page` (types in `types.ts`).

## Add a post
Create `posts/<yyyy-mm>-<slug>.json`:

```json
{
  "id": "unique-slug",
  "kind": "article | verse | hadith | announcement",
  "title": { "de": "...", "en": "..." },
  "body": { "de": "...", "en": "..." },
  "verseKey": "2:255",
  "hadithId": "bukhari:1",
  "image": "(optional, only existing files under public/)",
  "source": "Quran.com",
  "sourceUrl": "https://...",
  "tradition": "all | sunni | shia",
  "publishAt": "2026-10-21T00:00:00Z",
  "expiresAt": "2026-12-31T00:00:00Z"
}
```

- Never type Quran or hadith text by hand: set `verseKey` / `hadithId`; the app loads the text from the source.
- `hadithId` numbers are hadith-api numbers (the text is fetched by them). Labels and sunnah.com links show the usual
  number instead (`src/lib/hadithNumber.ts`, app copy in `mobile/src/web`): `muslim:1874` reads "Sahih Muslim 804" and
  links to sunnah.com/muslim:804a. The other collections number alike in both.
- `publishAt` in the future = scheduled. Invalid files are skipped (see server log), they do not break the feed.
- Changes show up after deploy (posts are re-read every 60 s, CDN caches up to 5 min).

## Remote config
Edit `config.json` and bump `version`. Deeplinks use the app scheme `quranmasterclass://<route>` (expo-router path). Labels: all 14 app locales, missing ones fall back to en. Promo ids the app renders natively: shams, pro, dua, name; other ids are shown as a plain card with title + deeplink. Announcements appear between `startsAt` and `endsAt`.

## Server corpus (endless `/api/feed/page`)
`feed_items` (db/schema.sql) holds 200,000+ posts as references only (verse keys, hadith collection:number, tafsir id +
verse key, name index, qbank id, lesson id, Wikipedia catalog title, lemma, dua id, mutashabihat group, maqasid section);
no Quran, hadith, tafsir or article text is stored. Fill or refresh it on the server (idempotent, safe to re-run):

```bash
sudo -u tafsir bash -lc "cd /srv/tafsirflow/app && node scripts/feed-corpus.mjs"
```

`--dry-run` builds and counts without the database, `--only=hadith,verse` limits the kinds, `--samples` prints examples.
`/api/feed/page?v=2&seed=<install seed>` walks a per-install shuffled order (src/lib/feed/corpus.ts) with variety rules,
the tradition filter and language availability; `nextCursor` is never null (a finished stream starts again in a new
order). Without `v=2` (older app builds) only verse and hadith posts come, as `editorial` items. Without the corpus (no
database, empty table) the previous day-by-day page answers. Weights per corpus kind and the app's share of corpus posts:
`corpus` in `config.json`.

## Website feed (/[locale]/feed and the home section)
The website shows the same corpus with the app's card designs (emerald and gold): `GET /api/feed/web?v=2&locale&tradition&seed&cursor&limit[&kinds=hadith,quiz&topic=hadith]`
returns resolved cards (`WebCard`, src/lib/feedWeb/types.ts; the texts come from the sources, resolvers in src/lib/feedWeb/*, the quiz bank is
generated by `node scripts/sync-qbank-web.mjs`). The browser keeps a seed (`qmc.feed-seed`) and the place in the stream (`qmc.feed-corpus-cursor`) in
localStorage, like the app. Tabs Home, Reels and Explore are in src/components/feed/*; the share images (story 9:16, 4:5, 1:1, five designs) are drawn
in the browser from src/lib/share/* (port of mobile/src/features/share). The app's texts are copied to src/lib/feedWeb/texts/<lang>.json with
`node scripts/extract-app-texts.mjs` (run it again when the app texts change). Story circles: `GET /api/feed/stories?locale[&full=1]`.

## Carousels and wisdom posts (`carousels/`)
Instagram-style carousels (cover, 3–8 numbered slides, a final slide with the sources and quranmasterclass.com/app) and
single-image wisdom posts, in the editors' own words: `carousels/data/<series>.json` and `carousels/wisdom/<set>.json`
(en, de, ar inline; the other app languages in `carousels/i18n/<lang>/<file>.json`, missing texts fall back to English).
Scripture is never in these files: a slide carries a verse key, a hadith reference (bukhari | muslim | nawawi : number,
hadith-api numbering) or a Hisnul Muslim id (`hisn:<chapter>:<index>`); app and website load the text from the source.
Schema: `carousels/types.ts`. Every new carousel has `needs_review: true` until a scholar has checked it.

Check the files (add `--refs=<dir>` for the source checks described in the script) and load their ids into `feed_items`
(kind `carousel` and `wisdom`, references only; safe to re-run, removed ids are pruned):

```bash
node scripts/carousels-load.mjs --check
sudo -u tafsir bash -lc "cd /srv/tafsirflow/app && node scripts/carousels-load.mjs"
```

`/api/feed/page` mixes them in for clients that send `carousels=1` (weights `carousel` / `wisdom` in `corpus.kindWeights`);
older app builds never get them. `/api/feed/carousels` lists them (gallery, `?resolved=1` with scripture), the website
shows them at `/[locale]/carousels` and in its feed. Nahj al-Balagha wisdom posts (Shia mode) are made in the app only.
